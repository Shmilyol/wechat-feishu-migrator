# 微信收藏表情迁移到飞书：独立实现设计草案

状态：已按本设计实现独立提取、下载和 Windows 整批选择，处于离线验证与 Windows 实机验收阶段。2026-10-30 用户要求按最新 Windows 微信适配，官网当前公开版本为 4.2.0；4.1.15 为用户原有版本。

## 目标

在用户自己的电脑上读取已登录微信的个人收藏表情，保存原始图片，整理成每批最多 50 张，通过飞书桌面客户端加入个人表情收藏。优先 Windows，保留现有 macOS 能力。最终运行不要求安装或调用 wxemoticon。

50 张是用户给定的单次导入数量上限，不是累计收藏数量或上传成功保证。保持原有动画，不默认把 GIF 转为静态图。

## 已知事实与待确认项

- 参考项目已支持 Windows 微信 4.x；其收藏元数据位于加密 emoticon.db 中。
- 参考项目区分 Windows 微信 4.0.x 与 4.1+ 的密钥处理方式，不能假设一个固定位置适配所有版本。
- 收藏顺序表包括 kFavEmoticonOrderTable、kCustomEmoticonOrderTable；元数据表包括 kNonStoreEmoticonTable。需要针对用户实际版本检查表结构，缺失时提示不支持，不把其他表情误作个人收藏。
- 元数据含图片 URL。可用地址可直接下载，但链接过期、缩略图、加密资源和缺失条目必须分别报告，不能用任意响应冒充图片。
- 飞书普通图片上传 API 的 image_key 不足以证明可写入个人表情收藏。设计继续走客户端已有添加入口。
- 用户提供原有版本 4.1.15，并要求以最新稳定版为适配目标。2026-10-30 官网公开 Windows 64 位版本为 4.2.0。当前开发环境为 macOS，无法替代 Windows 真实窗口验收。

## 方案比较

1. **读取微信数据库并下载原图（推荐）**：能保留收藏顺序、增量同步和较完整的图片集合；需要自研并维护 Windows 密钥读取及数据库兼容层。
2. **遍历微信本地图片缓存**：实现较少，但缓存可能不完整，混有缩略图或非收藏图片，不能作为完整迁移的唯一来源。可作为补充。
3. **逐个操作微信界面另存图片**：避免数据库兼容，但依赖界面布局、速度慢且难以证明没有遗漏。不作为主方案。

采用方案 1，同时保留本地图片分组输入，便于单独验证飞书导入，也可在特定微信版本暂不支持时处理已有图片。用户已要求自研并继续提供版本与适配目标。

## 实现边界

继续使用 Python 和现有分组清单，不引入 Web 服务或新的前端框架。仅把微信提取、图片存储、批次和客户端操作拆成职责明确的小模块。第三方通用库可用于加密、HTTP、窗口操作；不运行参考项目的二进制、脚本或远程服务。

参考公开的文件格式和行为，独立实现。当前没有在参考仓库文件树中发现许可证文件，许可证 API 返回 404；在许可情况明确前不直接复制其源码。

## 数据流程

### 1. 微信来源

- 发现或由用户指定 xwechat_files 根目录，列出账号，多个账号必须显式选择。
- 先做只读探测：微信版本、账号目录、emoticon.db 及其 WAL 是否存在。默认不修改微信目录。
- 为用户实际版本实现密钥读取与数据库验证；只处理用户自己的微信。提供显式密钥文件入口便于测试和兼容，但不把手动获取密钥作为最终正常使用的必要步骤。
- 密钥不放进命令行、日志、普通迁移清单。若需持久化，使用系统凭据存储；初版也可只驻留进程内存。
- 正确处理主数据库与 WAL 的一致性。不能只读主库而把最近收藏默默遗漏；无法取得可靠快照时明确停止并提示处理方式。
- 校验数据库页与实际表结构，按个人收藏顺序读取标识、原图候选地址。禁止把数据库中的全部表情直接宣称为个人收藏。

### 2. 下载与存储

- 记录账号、来源标识、收藏顺序、候选 URL、下载状态和本地文件摘要。
- 图片先写临时文件，检查真实文件签名和大小后再原子替换。限定请求超时和重试次数，拒绝把 HTML 错误页保存成 GIF。
- 以来源标识与内容摘要避免重复下载/重复分配；断网后可续传任务，不重新洗牌已有批次。
- 保留原始文件。不能确认是原图或需要额外解密时标记待处理，不静默替换成缩略图。

### 3. 飞书批次

- 复用 exported/1、exported/2 等目录以及稳定分组规则，每批至多 50 张。
- 旧 group_manifest.json 保持兼容；对旧数据计算摘要并补建新迁移记录，不能清空现有目录或尝试历史。
- 手动模式：打开当前批次目录，由用户在飞书选择并添加。
- 自动模式：校准添加入口，打开文件选择器，一次选择本批全部明确列出的文件并提交；使用原生多选或文件名列表，不用 Ctrl+A 误选非本批文件。
- 自动模式默认只试 1 张；显式批量后以最多 50 张为一批。图片格式或路径长度等不兼容时允许拆成更小批次。
- 验证当前前台窗口确属飞书进程；主窗口与文件对话框操作均失败即停，避免在其他软件中点击或粘贴。
- 导入后显示该批文件列表和数量，由用户确认成功后记录 confirmed。仅按键完成只能记为 attempted_unverified，不能记为成功。
- 部分成功时允许记录具体文件；重试只处理未确认文件。不能把整批已尝试等同于每张已添加，也不自动跳过真实失败项。

## 验收

- 无 wxemoticon 安装、无其缓存的 Windows 环境，完成账号发现、表情读取与图片下载。
- 对实际微信版本验证新增收藏也能读到，核对收藏数量、顺序及若干 GIF 动画。
- 用 0、1、49、50、51、101 张图片验证批次上限、顺序、去重和续跑。
- 覆盖中文及空格路径、断网失败、无效图片响应、缺失/错误密钥、不支持的表结构。
- Windows 飞书实机先导入 1 张，再导入含 50 张的批次，人工核查结果后才能宣称整批自动导入可用。
- 保留 macOS 回归测试；任何未实机验收的平台或版本在 README 明确标注。

## 当前实现状态

已用 wechat_source.py、windows_wechat.py、sticker_download.py 替换外部导出调用。Windows --import 实现最多 50 张的精确文件名列表选择、每批确认、部分成功与重试；macOS 自动模式仍逐张，手动模式可整批。保留旧缓存名称和清单以兼容已有数据。

Windows 密钥读取实现为 4.1+（4.x）x64 候选结构探测、实际 FILEVERSION 检测及数据库 HMAC 校验；结构不支持时明确失败。没有 Windows 实机结果，不能宣称微信 4.2.0 或 4.1.15 已验证兼容。macOS 当前独立导出需要已有密钥文件，未实现原先外部工具提供的自动取密钥能力。
